# 标析试用说明

面向版本：`v0.5.6-alpha.1`（源码试用版）。标析帮助整理招标要求、评分与风险，并把结果连回原文，供人工核对。

[返回演示与试用入口](README.md) · [可转发版本页](https://github.com/X9728771115-dotcom/biaoxi/releases/tag/v0.5.6-alpha.1) · [下载演示与试用资料包](https://github.com/X9728771115-dotcom/biaoxi/releases/download/v0.5.6-alpha.1/biaoxi-trial-v0.5.6-alpha.1.zip)

**第一次接触 GitHub，建议先走路线一。当前只提供源码，没有可双击安装的程序。** 两条路线都可以反馈，不需要公司文件、模型 API、密钥或平台账号。

## 路线一：先看演示，不安装

1. [打开演示视频（MP4，2 分 40 秒）](https://github.com/X9728771115-dotcom/biaoxi/releases/download/v0.5.6-alpha.1/biaoxi-demo-v0.5.6-alpha.1.mp4)，或查看[在线图解](README.md#先看四个关键画面)。视频由实际界面截图配字幕编排，不是连续录屏，无配音。下载并完整解压[资料包](https://github.com/X9728771115-dotcom/biaoxi/releases/download/v0.5.6-alpha.1/biaoxi-trial-v0.5.6-alpha.1.zip)后，也可直接播放其中的 `演示视频.mp4`，或用浏览器打开 `00-开始这里.html`。
2. 重点看四件事：上传文件 → 离线分析 → 查看评分和风险 → 回到原文核验。
3. 复制[试用反馈模板](feedback-template.md)填写，选择“仅看演示”，写下看不懂、操作不顺或希望改进的地方。资料包中另有 TXT、HTML 和 Markdown 三种格式，选一种即可。

这条路线记录为**演示反馈**，不计为成功安装或实际使用。视频中的结果来自合成样本，也不能证明真实项目分析准确。

## 路线二：从源码亲自操作

适合熟悉终端、Node.js 和 npm 的开发者；没有这方面经验，可请开发者协助，并如实记录“协助完成”。

### 1. 下载指定版本

- 打开 [v0.5.6-alpha.1 版本页](https://github.com/X9728771115-dotcom/biaoxi/releases/tag/v0.5.6-alpha.1)，展开页面下方的 **Assets**，点击 **Source code (zip)**。这是源码压缩包。
- 也可打开 [项目主页](https://github.com/X9728771115-dotcom/biaoxi)，点击绿色 **Code → Download ZIP**。此方式下载的是主页当前分支，可能与演示版本不同，请在反馈里注明。

把 ZIP 解压到一个新建的个人试用目录；不要覆盖已有“标析”目录，也不要把旧报告或公司材料复制进来。终端须进入解压后、能看到 `package.json` 的源码目录。下载源码不需要给维护者提供 GitHub 密码。

### 2. 检查环境并启动

先准备 **Node.js 22（至少 22.13，低于 23）、npm 10.9.8 和 Git 命令行工具**。ZIP 用户也应安装 Git，部分源码检查和测试需要它。已验证的准备环境为 Node.js 22.23.2、npm 10.9.8；其他系统与补丁版本仍需实测。

在源码目录逐行运行：

```sh
node --version
npm --version
git --version
npm ci
npm run dev:safe
```

首次安装需要联网下载依赖。若报错，保留错误信息并反馈；不要删除锁文件或随意升级依赖绕过问题。

成功后，在浏览器打开终端打印的地址，默认是 [http://127.0.0.1:43221](http://127.0.0.1:43221)。**以本次终端打印的实际 URL 为准**，终端保持运行。

若提示端口被占用，保留现有服务，请开发者确认另一个端口空闲后再启动。例如 `43222`：

macOS / Linux：

```sh
BIAOXI_PORT=43222 npm run dev:safe
```

Windows PowerShell：

```powershell
$env:BIAOXI_PORT = '43222'
npm run dev:safe
```

示例端口也可能被占用。不要为了试用停止其他服务。完成后，在启动服务的同一终端按 `Ctrl+C` 停止自己启动的浏览器服务。

需要试桌面开发窗口时，使用 `npm run start:safe`，并正常退出窗口。它是开发入口，不是安装包；浏览器版不能据此验证桌面网页 AI 流程。

### 3. 用合成样本完成一次核对

1. 打开“上传招标文件”，点击上方“点击选择文件，或拖到这里”区域，选择资料包中的 `合成样本/综合招标-测试用途.txt` 作为主招标文件；源码中的同名样本位于 [`tests/fixtures/`](../../tests/fixtures/综合招标-测试用途.txt)。先用 TXT，PDF 可另开一次对比，不必同时选择两份。
2. 保持“离线分析”，不配置 AI，不上传企业材料，点击“开始分析”。
3. 查看四项重点输出：废标项清单、必须加分项、必须承诺内容、投标可行性结论；再查看 14 类详细分析。
4. 核对评分明细：**10 项，共 100 分**。其中商务 4 项 / 20 分、技术 3 项 / 40 分、报价 1 项 / 30 分、附加 2 项 / 10 分。这里是条款分值，不是企业已经取得的得分。
5. 打开至少一条评分和一条风险的原文出处，逐字比较。宽屏中原文在左侧“招标文件原文”面板；TXT 按章节显示，必要时在该面板滚动查看高亮文字，不能把章节标签当成已经核实。再检查这些刻意设置的边界：样品未提供对应项不得分；强制节能证明与环保加分分开；两处截止日期冲突应待澄清。
6. 未提供企业资料，不应直接认定企业符合或不符合资格；可行性结论应保持“待核验”。正文提到附件 A/B，不等于附件完整正文已上传或核验。无需为了本次试用补交公司资料。
7. 可尝试导出 PDF / Word，并检查是否可打开、中文与出处是否清楚；未执行就记录“未执行”。回到“报告记录”，刷新页面后确认刚才的报告仍在。

样例中的机构、金额、账号和日期均为虚构，仅用于测试。它不是现行采购政策或真实项目依据。

### 4. 数据保存在哪里

按上述安全启动命令，浏览器试用数据保存在本次源码目录的 `candidate-data/web`；桌面开发数据在 `candidate-data/desktop`，报告位于其 `data` 子目录。入口不会迁移、清理或覆盖原有安装数据。不要直接用 `electron .` 或底层入口启动。

这轮只用合成资料。默认离线分析在本机进行；主动选择联网模式并开始任务会向相应服务商发送材料，本轮不需要开启。

## 怎样反馈

填写[试用反馈模板](feedback-template.md)，或资料包中的同名 TXT / Markdown 版，通过邀请人约定的方式交回即可；无需注册 GitHub。熟悉 GitHub 的试用者也可在 [Issues](https://github.com/X9728771115-dotcom/biaoxi/issues) 提交不含敏感信息的问题。

截图或日志先去掉姓名、账号、密钥、个人路径和真实文件名。不要上传公司原件、证照或业务报告。私下交回的反馈默认不公开；只有你明确同意的内容和身份，才可整理公开。Issue 本身公开，请自行决定是否提交。反馈用于安排后续改进，没有固定答复或修复时限。

源码和自动化检查通过，不代表真实项目逐项验收通过。当前真实模型 API、真实平台账号流程、安装包和部分目标设备仍有未执行项，详见仓库 [功能与边界](../features-and-limits.md)与[验证记录](../validation.md)。
